# Footballymba Backend API

Бэкенд-служба системы автоматизации любительского футбольного сообщества «Футболямба». Данный сервис является главным источником правды для базы данных и предоставляет единый REST API для веб-клиента (React) и Telegram-бота (Python).

---

## 1. Описание системы и стек технологий

### Общая идея системы
Ранее сообщество «Футболямба» функционировало исключительно в Telegram через бота. Переход на веб-платформу решает задачи расширения функционала (ведение статистики, профили игроков, управление турнирами и драфтом). 
Java-бэкенд объединяет все каналы взаимодействия: обрабатывает запросы от веб-интерфейса и является защищенным API для выполнения команд из Telegram-бота.

### Стек технологий
*   **Ядро:** Java 21 (Eclipse Temurin) + Spring Boot 3.5.x
*   **Безопасность:** Spring Security + JWT (io.jsonwebtoken) + BCrypt (хэширование паролей)
*   **База данных:** PostgreSQL 14+ + Hibernate/JPA (ORM)
*   **Миграции:** Flyway (управление версиями БД)
*   **Инфраструктура:** Docker + Docker Multi-stage сборка
*   **Утилиты:** Lombok (генерация бойлерплейта), Jakarta Validation (валидация входящих данных)

### Структура каталогов проекта
Проект спроектирован по принципу **Package-by-Feature (Пакет-по-фиче)**. Бизнес-логика разделена на независимые вертикальные модули (фичи).

```text
src/main/java/com/footballymba/api/
├── FootballymbaApplication.java    # Точка входа в приложение
├── config/                         # Глобальные конфигурации (БД, Безопасность)
│   └── SecurityConfig.java         # Настройка доступов, BCrypt и бинов сессий
├── exception/                      # Слой обработки ошибок
│   ├── ErrorResponse.java          # Единый формат JSON-ответов для ошибок
│   ├── GlobalExceptionHandler.java # Перехватчик ошибок со всех контроллеров
│   ├── ResourceNotFoundException.java # Ошибка: Сущность не найдена в БД
│   └── UnauthorizedException.java     # Ошибка: Отказ в авторизации (пароль/токен)
├── security/                       # Компоненты криптографии и JWT
│   └── JwtTokenProvider.java       # Генератор безопасных токенов авторизации
└── features/                       # Вертикальные бизнес-модули
    ├── auth/                       # Модуль авторизации и входа
    │   ├── controller/             # REST-эндпоинты (вход по паролю/по ссылке)
    │   ├── service/                # Бизнес-логика валидации и выпуска токенов
    │   ├── dto/                    # Объекты приема/отдачи данных (JSON)
    │   ├── entity/                 # Модель одноразовых токенов (magic_tokens)
    │   └── repository/             # Интерфейс работы с таблицей токенов
    └── player/                     # Модуль игроков
        ├── entity/                 # Модель игрока (players)
        └── repository/             # Доступ к таблице игроков (поиск, проверки)
```

## 2. Варианты развертывания

Сервис поддерживает три гибких режима запуска в зависимости от твоих задач.

### Вариант 1: Полностью локальный запуск (CLI / IDE)
Используется, если на твоем компьютере (например, Mac) локально установлена СУБД PostgreSQL.

1. Убедись, что локальная БД запущена на порту `5432`, создана база `footballamba_db` и применен твой начальный дамп.
2. Проверь настройки в `src/main/resources/application.yml` (секция `spring.datasource`).
3. Выполни очистку и запуск в терминале:
   ```bash
   mvn clean spring-boot:run
   ```
   *При первом старте Flyway автоматически применит миграцию V2, добавив нужные таблицы.*

---

### Вариант 2: Полностью через Docker (Репозиторий `footballymba-platform`)
Используется для деплоя на сервер или полноценного локального тестирования всей системы (React + Бот + Java + Postgres).

1. Все настройки сборки описаны в корневом `Dockerfile` проекта с использованием эффективного **Multi-stage** подхода.
2. Оркестрация осуществляется в главном репозитории платформы `footballymba-platform` через глобальный `docker-compose.yml`.
3. Java-приложение конфигурируется через переменные окружения, переопределяющие дефолты из `application.yml` (например, `SPRING_DB_URL`, `BOT_INTERNAL_SECRET`, `JWT_SECRET_KEY`).

---

### Вариант 3: Гибридный режим (Рекомендуемый для разработки)
Идеально подходит для ежедневной работы. База данных PostgreSQL крутится изолированно в Docker, а Java-код ты запускаешь и дебажишь локально из IDE.

1. Запусти контейнер с PostgreSQL одной командой в терминале:
   ```bash
   docker run --name footballymba-db \
     -e POSTGRES_DB=footballamba_db \
     -e POSTGRES_USER=george \
     -e POSTGRES_HOST_AUTH_METHOD=trust \
     -p 5432:5432 \
     -d postgres:14-alpine
   ```
   *(Данная команда поднимет чистую базу Postgres на порту 5432 без пароля).*
2. Накати свой дамп базы данных на этот Docker-контейнер:
   ```bash
   psql -h localhost -U george -d footballamba_db -f path_to_your_dump.sql
   ```
3. Запусти бэкенд локально из IntelliJ IDEA или терминала (`mvn spring-boot:run`). Он автоматически подключится к БД, запущенной в Docker.

## 3. Архитектура безопасности (JWT + HttpOnly Cookies)
В проекте реализована передовая двухтокенная схема авторизации (**Access + Refresh Tokens**), полностью соответствующая стандартам безопасности OWASP для одностраничных приложений (SPA) [3].

```
[ Браузер ] ──(Отправляет логин/пароль)──► [ Бэкенд (Java) ]
[ React ] ◄──(Возвращает Access Token в JSON)──────────── [ Бэкенд ]
[ Браузер ] ◄──(Автоматически сохраняет HttpOnly Cookie)── [ Бэкенд ]
```

### Как это устроено:

1. **Access Token (Время жизни: 30 минут):**
   * Хранится **исключительно в оперативной памяти** React-приложения (например, в Redux State) [3].
   * При закрытии вкладки или обновлении страницы (`F5`) этот токен полностью стирается [3].
   * **Защита:** Поскольку токен не хранится в `localStorage` или `sessionStorage`, его невозможно украсть с помощью XSS-атак (внедрения вредоносного JS-кода) [3].

2. **Refresh Token (Время жизни: 7 дней):**
   * Хранится в базе данных (`refresh_tokens`) и привязан к конкретному игроку [3].
   * Передается клиенту в виде скрытого HTTP-заголовка `Set-Cookie` со следующими флагами безопасности [3]:
     * `HttpOnly` — запрещает доступ к куке из JavaScript [3]. Её невозможно прочитать или украсть кодом.
     * `Secure` — кука передается только по зашифрованному протоколу HTTPS (включается автоматически через переменную `COOKIE_SECURE` на проде).
     * `SameSite=Lax` — браузер блокирует отправку куки при запросах со сторонних вредоносных сайтов, что полностью защищает от атак класса **CSRF** (Cross-Site Request Forgery).

3. **Тихое обновление (Silent Refresh) и Ротация:**
   * Каждые 30 минут (или при перезапуске вкладки) React делает тихий фоновый запрос на `/api/v1/auth/refresh`. Браузер сам прикрепляет скрытую куку.
   * Бэкенд проверяет старый Refresh-токен, удаляет его из БД, генерирует новый Access-токен (в JSON) и присылает **новый** Refresh-токен в куке (это называется **ротацией**).
   * **Защита от кражи кук:** Если хакер украдет куку и попытается применить её, бэкенд зафиксирует повторное использование уже удаленного токена, мгновенно аннулирует все сессии этого пользователя и заставит его войти заново, заблокировав хакера.

4. **Безопасный Logout (Выход):**
   * При выходе бэкенд удаляет токен из базы данных [3].
   * Сервер посылает браузеру команду очистки куки (`Max-Age=0`) [3]. Даже если старая кука осталась в памяти у злоумышленника, бэкенд не найдет её в БД и вернет `401 Unauthorized` [3].

## 4. Описание фич (Business Features) и API эндпоинтов

### Фича: `auth` (Авторизация и Связывание)
Отвечает за безопасный доступ пользователей к веб-платформе. Поскольку в базе данных уже есть реальные игроки из Telegram, фича реализует бесшовный гибридный вход.

#### Бизнес-логика:
1.  **Вход по "Волшебной ссылке" (Magic Link):** Игрок запрашивает ссылку в Telegram-боте. Бэкенд генерирует защищенный временный токен в БД (`magic_tokens`) и отдает ссылку боту. Юзер кликает по ссылке, бэкенд проверяет токен, удаляет его и авторизует пользователя, выдав ему криптографический веб-паспорт — JWT-токен.
2.  **Задание учетных данных (Onboarding):** Если пользователь вошел впервые через бота, бэкенд сигнализирует фронтенду, что пароль еще не задан. Пользователь придумывает пароль прямо на сайте (хэш сохраняется в `players.password_hash`).
3.  **Классический вход:** При последующих визитах пользователь входит напрямую по никнейму (`nickname` из БД) и паролю без участия бота.

Базовый префикс всех путей: `/api/v1/auth`

| Метод | Эндпоинт | Кто вызывает | Описание | Защита / Заголовки |
|:---|:---|:---|:---|:---|
| `POST` | `/magic-link` | Python-бот | Генерация токена и ссылки для входа | `X-Internal-Secret` (Секретный ключ связи) |
| `POST` | `/magic-login` | React-клиент | Вход по ссылке из Telegram | Публичный (Устанавливает HttpOnly Cookie) [3] |
| `POST` | `/login` | React-клиент | Классический вход по нику и паролю | Публичный (Устанавливает HttpOnly Cookie) [3] |
| `POST` | `/refresh` | React-клиент | Фоновое обновление сессии (Silent) | Читает `refreshToken` из Cookie [3] |
| `POST` | `/logout` | React-клиент | Выход и очистка сессии | Читает `refreshToken` из Cookie [3] |

---

#### Спецификация API Эндпоинтов

##### 1. Создание одноразового токена (Запрос от Telegram-бота)
*   **Метод:** `POST`
*   **Путь:** `/api/v1/auth/magic-link`
*   **Заголовки безопасности:**
    *   `X-Internal-Secret`: `4f9d2a8b3c...` (Секретный ключ связи Бот-Java. Запросы без ключа или с неверным ключом отклоняются со статусом `401 Unauthorized`).
*   **Тело запроса (JSON):**
    ```json
    {
      "tgId": 12345678
    }
    ```
*   **Ответ (200 OK):**
    ```json
    {
      "token": "a1b2c3d4-e5f6...",
      "loginUrl": "http://localhost:3000/auth/callback?token=a1b2c3d4-e5f6..."
    }
    ```

---

##### 2. Авторизация по одноразовой ссылке (Запрос от React-клиента)
*   **Метод:** `POST`
*   **Путь:** `/api/v1/auth/magic-login`
*   **Параметры запроса (Query Params):**
    *   `token` (строка, UUID токен, полученный из ссылки)
*   **Ответ (200 OK):**
    ```json
    {
      "accessToken": "eyJhbGciOiJIUzI1NiJ9...", // JWT токен для авторизации будущих запросов
      "nickname": "george_best",
      "isPasswordSet": false                    // true - если пароль уже задан, false - если нужно направить на создание пароля
    }
    ```
*   **Ошибки (401 Unauthorized):** Возвращается, если токен не существует или срок его жизни (5 минут) истек.

---

##### 3. Классический вход по логину и паролю (Запрос от React-клиента)
*   **Метод:** `POST`
*   **Путь:** `/api/v1/auth/login`
*   **Тело запроса (JSON):**
    ```json
    {
      "nickname": "george_best",
      "password": "my_secure_password"
    }
    ```
*   **Ответ (200 OK):**
    ```json
    {
      "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
      "nickname": "george_best",
      "isPasswordSet": true
    }
    ```
*   **Ошибки (401 Unauthorized):** Возвращается при неверном нике/пароле или если пользователь еще не задал пароль в своем профиле (требуется войти через бота).

---

##### 4. Тихое обновление токенов (Запрос от React-клиента)
*   **Метод:** `POST`
*   **Путь:** `/api/v1/auth/refresh`
*   **Требования:** Фронтенд должен отправлять запрос с флагом `withCredentials: true` (чтобы браузер автоматически прикрепил куку) [3].
*   **Ответ (200 OK):**
    *   **Тело ответа (JSON):**
        ```json
        {
          "accessToken": "eyJhbGciOiJIUzI1NiJ9... (новый Access Token)",
          "nickname": "george",
          "isPasswordSet": true
        }
        ```
    *   **Заголовки ответа (Headers):**
        *   `Set-Cookie`: `refreshToken=c5d6... (НОВЫЙ ротированный токен); Max-Age=604800; Path=/api/v1/auth; HttpOnly; SameSite=Lax` [3]
*   **Ошибки (401 Unauthorized):**
    ```json
    {
      "timestamp": "2026-09-04T12:00:00",
      "status": 401,
      "error": "Unauthorized",
      "message": "Сессия отсутствует. Войдите в аккаунт."
    }
    ```

---

##### 5. Выход из аккаунта (Запрос от React-клиента)
*   **Метод:** `POST`
*   **Путь:** `/api/v1/auth/logout`
*   **Требования:** Фронтенд отправляет запрос с `withCredentials: true` [3].
*   **Ответ (204 No Content):**
    *   Бэкенд удаляет токен из базы данных [3].
    *   **Заголовки ответа (Headers):**
        *   `Set-Cookie`: `refreshToken=; Max-Age=0; Path=/api/v1/auth; HttpOnly; SameSite=Lax` (команда браузеру стереть куку) [3]
